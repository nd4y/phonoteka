# YouTube и происхождение скачанного аудио

Фонотека разделяет музыкальную запись и конкретное исходное видео. Shazam помогает определить композицию, но одно совпадение отпечатка не устанавливает, из какого клипа, концерта или перезалива скачан файл.

## Локальное восстановление

Сканирование и задание `youtube` читают:

- Ссылки из ID3 COMM/WXXX/WOAS/WOAF, пользовательских полей URL, MP4 purl/comment, Vorbis comments и тегов WebM/Matroska.
- ID в конце стандартного имени `Название [VIDEO_ID].ext` и прежнего `Название-VIDEO_ID.ext`. Это кандидат, а не подтверждение происхождения.
- Соседний `Название.info.json`, `Название.ext.info.json`, а также вариант после удаления суффикса формата `.f251`. Из JSON сохраняются только разрешенные сведения об ID/ссылке; playlist JSON не относится к отдельному треку. Размер ограничен 2 МиБ, символические ссылки не читаются.
- Для производных аудиофайлов сохраняется связь с источником, включая CUE. Связь с видео всего альбома не означает, что видео соответствует длительности отдельной композиции.

Одна однозначная ссылка в тегах/sidecar получает статус `recorded`: происхождение записано в локальных метаданных. Разные ID приводят к `conflict`. Ручной выбор имеет статус `owner_confirmed`; он не меняется при повторном сканировании или записи музыкальных тегов. После снятия связи автоматическое повторное присоединение выключено до выбора владельцем.

Это соответствует поведению yt-dlp: `--embed-metadata` сохраняет исходный `webpage_url` в purl/comment, а `--write-info-json` создает файл сведений. Стандартное имя содержит ID. См. [официальную документацию yt-dlp](https://github.com/yt-dlp/yt-dlp#modifying-metadata).

## Сетевые запросы

`YOUTUBE_ENABLED=true` отдельно разрешает запросы публичных метаданных YouTube. По умолчанию выключено. Локальные сведения доступны всегда.

- Проверка известного ID выполняется через oEmbed: название и канал, без HTML-вставки и внешних изображений. Недоступность видео сохраняется отдельно от происхождения; удаление, ограничение доступа и временная блокировка не различаются без достаточных данных.
- Если локальной связи нет, yt-dlp 2026.8.19 получает до трех результатов публичного поиска в режиме flat playlist и skip download. Приоритет запроса: результат Shazam, затем музыкальные теги, затем подсказка имени файла. Название/исполнитель отправляются YouTube; аудио не отправляется и не скачивается. Cookies браузера, аккаунт YouTube и пользовательские конфиги yt-dlp не используются.
- Показываются канал, длительность и разница длительности. Даже точное совпадение названия и длительности остается кандидатом до решения владельца. Проверка доступности ID не подтверждает идентичность аудио.
- Действуют кеш, ограничение частоты, суточный бюджет и сохраненная очередь повторов при временных отказах. Поиск без ключа зависит от доступности публичного YouTube и может быть ограничен сервисом.

## Интерфейс и API

В карточке трека доступны чтение локальных источников, поиск/проверка видео, ручная ссылка, подтверждение кандидата и снятие связи. В отчетах есть массовые действия и счетчики статусов. Запись ссылок меняет каталог, а не музыкальные теги и текст песни. Исходные встроенные URL сохраняются существующим редактором; новые подтвержденные связи входят в JSON/CSV и манифест Ready.

`POST /api/jobs`, `kind: youtube`, поддерживает `track_ids` или `params.scope: all|pending`. Без параметров работает только локально. `youtube_lookup: true` проверяет известные видео; `youtube_search: true` дополнительно ищет кандидатов для отсутствующих связей и требует `youtube_lookup`. Задания требуют Idempotency-Key; API-токену нужна область jobs:analysis.

`PUT /api/tracks/{id}/youtube` с `{ "url": "https://www.youtube.com/watch?v=VIDEO_ID" }` подтверждает связь. `url: null` снимает ее. Требуются сессия владельца, CSRF и текущий If-Match. API-токен не может выдавать автоматическое решение за подтверждение владельца.

## Будущие загрузки

Для сохранения происхождения используйте ID в имени, `--embed-metadata` и `--write-info-json`. Храните sidecar рядом с итоговым аудио. Фонотека не запускает новые скачивания и не использует произвольные URL из JSON как команды или адреса загрузки.

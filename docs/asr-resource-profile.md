# Ресурсный профиль ASR

Поддерживаемый CPU-профиль `cpu-small-int8-supervised-v2`: один резидентный faster-whisper small int8 с закрепленной ревизией. Transcribe и forced alignment используют один дочерний model worker последовательно. API/очередь находятся в родительском процессе. GPU остается опциональным и этим профилем не включается.

Контракт `transcribe-v3` включает ревизию ресурсного профиля в идентичность задания. App и inference обновляются вместе; несовместимый endpoint получает видимую ошибку до отправки аудио. Старые результаты сохраняются под прежними ID.

Лимиты: 1800 секунд входа, исходные 1..8 каналов и частота до 384 кГц; анализ в mono 16 kHz, не более 28 800 000 PCM samples, WAV до 60 МиБ, 20000 выходных слов и 8 МиБ JSON-результата. Длительность, число каналов и частота входа проверяются до загрузки модели, декодированное число samples проверяется отдельно. Обычный stereo и поддержанное многоканальное аудио сводятся в mono только для анализа. FFmpeg имеет deadline 600 секунд, spool stdout/stderr ограничен 32/1 МиБ. Сжатый файл не обходит декодированные лимиты. PCM хранится в отдельном временном каталоге родителя и удаляется также после аварии model worker.

Входной JSON до 1 МиБ и результат до 8 МиБ передаются через input.json/output.json в приватном каталоге задания с правами 0700, файлы имеют права 0600. IPC содержит только короткую ссылку входа и сообщения loaded/result/error; frame ограничен 4096 байт. Parent принимает результат только из ожидаемого output.json этого задания, не доверяет пути из сообщения child, проверяет nofollow, regular file, nlink и размер. Большие payload не блокируют deadline внутри pipe. При завершении задания или контролируемом отказе каталог удаляется.

Общий RSS model worker и непосредственного decoder проверяется каждые 100 мс с лимитом 2 ГиБ. Поддерживаемый контейнер имеет жесткий cgroup memory limit 3 ГиБ для API, весов, буферов и page cache. Монитор RSS допускает краткий выброс между измерениями; hard limit задает Docker. Model worker имеет отдельную process group: при отказе завершаются только он и его decoder, API продолжает работать. Профиль повышает OOM priority дочернего процесса, если ядро разрешает это действие. SIGKILL сам по себе не называется доказанным OOM.

Deadline одного выполнения 6600 секунд. MemoryError/model OOM, превышение бюджета, timeout и аварийное завершение имеют отдельные reason codes. Отказ выгружает модель; автоматического повторения той же задачи или бесконечного fallback нет. Новое поколение запускается явным повтором владельца. Запуск, выполнение и выгрузка имеют одного serial lifecycle owner. Shutdown выставляет stop event, запрещает новый spawn, дожидается рабочего потока и освобождает handles под тем же lock. Другие модели/URL пользовательским запросом не выбираются.

`/health` публикует профиль, Prometheus - текущий/пиковый sampled RSS, число запусков процесса и residency. PID, пути и слова не являются labels. Unit regression использует настоящие отдельные процессы для residency, timeout, memory budget, modeled OOM, crash, зависшего получателя большого входа, oversized result header и гонок shutdown/start. Рисковые сценарии имеют внешний 10-секундный watchdog. Проверка pinned реальной модели и распознавания выполняется `tests/inference_smoke.py` в CI. Эти проверки не заменяют музыкальный пилот точности и длинный нагрузочный профиль на целевом хосте.

# Сверка конкретного издания альбома

В «Отчетах» блок «Сверка конкретного релиза» сравнивает явно выбранные файлы с конкретным MusicBrainz release. Название album в тегах лишь помогает выбрать группу файлов. Оно не подтверждает комплектность, издание, исполнение или состав deluxe/переиздания.

1. Выберите группу и проверьте список ее файлов. Исключите другое издание или ненужные дубли; профиль ограничен 200 файлами.
2. Укажите UUID либо ссылку конкретного MusicBrainz **release**, включая нужную страну/дату/издание. Recording ID и Release Group ID не заменяют release. Единственный общий embedded Release ID может быть подставлен как подсказка, но запуск остается явным действием владельца.
3. Запустите сверку. Задание `release_audit` получает только публичный список релиза. Аудио, пользовательские пути и теги файлов этим запросом не передаются. Для запуска требуется существующее согласие `EXTERNAL_METADATA=true`.
4. Проверьте позиции по дискам, отсутствующие композиции, дубли номеров, лишние/неопределенные файлы и конфликты ID/названия/исполнителя/длительности. Для сборника сравнивается исполнитель каждой композиции, а не требование одного исполнителя на весь альбом. Допуск длительности составляет 2 секунды.
5. Если коллекция намеренно частичная, включите ожидаемое подмножество, отметьте нужные позиции и сохраните причину. Версии решения сохраняются. «Подмножество собрано» не означает «весь релиз полный». Отсутствующая композиция не считается поврежденным файлом и не скачивается.

Сопоставление использует Release Track ID, Recording ID и disc/track position; название и длительность остаются проверяемыми признаками. Противоречащий embedded Release ID не игнорируется. Одно совпавшее имя альбома не дает `complete`; неизвестная позиция или измененная ревизия оставляют `unknown`. Совпадение по метаданным не называется подтвержденной аудиоидентичностью. При нехватке эталонных данных, 404 или обрезанном ответе полнота не выдумывается.

Проверка не меняет музыку, не создает групповые теги/обложку и не выбирает preferred copy вместо владельца. Album ReplayGain можно отдельно запросить для сохраненного, однозначно сопоставленного ожидаемого состава; это новое явное задание. Правильность тегов, качество аудио, комплектность и допуск отдельного файла в Ready остаются независимыми показателями.

Для принятых файлов доступен отдельный блок [групповых предложений тегов/обложки](album-batch.md). Он учитывает ID/версию этой сверки, индивидуальные исключения и права источников; запись аудио остается отдельным действием в карточке.

Сеть выполняется в существующем worker через тот же `Providers`, вместе с его budget/cache/retry и MusicBrainz spacing 1.1 секунды. При 429/outage/quota задача получает durable `waiting_provider`; ожидающие файлы не становятся completed. После перезапуска прерванное read-only задание можно запустить заново; действительный кеш не требует повторного внешнего вызова. Новый app следует поставлять вместе с новым worker, который знает `release_audit`.

Tracklist ограничен 50 дисками/1000 композициями и лимитом ответа существующего провайдера. Полный список сохраняется только в пределах разрешений и срока исходного кеша: cache hit не продлевает TTL путем создания новой сверки. Истечение или отзыв разрешения скрывает эталон и возвращает unknown; cleanup/backup redaction применяют тот же gate. Нормализованный список не превращается в бессрочную копию запрещенного кеша. Сохраненные owner subset decisions содержат номера позиций и причину.

API:

- `POST /api/jobs`, `Idempotency-Key`, JSON `{"kind":"release_audit","track_ids":["file-uuid"],"params":{"release_id":"release-uuid"}}`.
- `GET /api/release-reviews` - последние 50 сверок; `GET /api/release-reviews/{id}` - актуальное сравнение с frozen file IDs/SHA. Измененная revision делает старую сверку stale/unknown.
- `GET /api/release-reviews/members?ids=id1,id2` - ограниченный список выбранных файлов для проверки состава.
- `PUT /api/release-reviews/{id}`, owner session + CSRF, JSON `{"base_version":1,"expected_slots":["1:1","1:2"],"note":"Храню только первый диск"}`. `expected_slots:null` возвращает ожидание всего релиза. Устаревшая версия/файл дает 412.
- `GET /api/release-reviews/{id}/export/json` либо `/csv` - отчет с разрешенным содержимым. CSV защищает формулы. Неизвестность/частичность не скрываются в JSON.

Контракт и ошибки проверяются разрешенными фикстурами в [test_release_review.py](../tests/test_release_review.py). Это не доказательство доступности живого MusicBrainz; официальный сайт при чтении документации в этой сессии возвращал HTTP429. Текущие CI/build-01 результаты фиксируются отдельным CHECK в [реестре](requirements-register.md).

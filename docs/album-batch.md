# Групповые предложения тегов и обложки

Блок «Групповые предложения тегов и обложки» работает с явно выбранным составом до 200 файлов. Он доступен для группы из отчета или однозначно сопоставленного полного релиза/ожидаемого подмножества. Группировка по названию альбома сама не подтверждает конкретное издание.

1. Откройте подготовку пакета. Контекст загружается по кнопке, без запросов для всех закрытых альбомных групп.
2. Отметьте изменяемые поля. Неотмеченные сохраняются. Для принятого MusicBrainz release можно явно выбрать поля из эталона; сервер связывает их с ID/версией сверки и реальным источником, а не доверяет переданному клиентом provenance.
3. При необходимости загрузите общую обложку JPEG/PNG до 10 МиБ либо выберите найденный источник. Сервер проверяет фактический формат/размер/изображение. Выбор найденной обложки связан с ID кандидата и текущей ревизией исходного файла; ограничения источника сохраняются.
4. Настройте индивидуальные исключения: исключить файл, не менять отдельное поле/обложку, задать собственное значение для одного файла. Закрепленные поля по умолчанию пропускаются с явным списком. Можно выбрать строгий режим, блокирующий весь пакет. Прямое индивидуальное переопределение закрепленного поля запрещено до снятия закрепления.
5. Нажмите «Показать изменения для каждого файла». Проверьте before/after, исключения, недоступные профили и ошибки прав. При ошибке можно исключить конкретный файл и построить новый предпросмотр. Изменение параметров инвалидирует старый preview.
6. Сохраните предложения. В одной SQLite transaction повторно проверяются SHA каждого включенного файла, актуальный proposal, locks, источник/права и принятый состав релиза. Либо сохраняются все допустимые предложения, либо ни одно. Отказ вставки в середине также откатывает первую вставку и события.

Неизмененные файлы отмечаются `unchanged`, исключенные входят в manifest с причиной. Существующее актуальное предложение объединяется с групповыми полями: сторонний текст, обложка и прочие поля/происхождение сохраняются. Известные ограничения provider-acquired данных не исчезают после копирования в ручной ввод. Противоречие/истекший срок хранения дает видимую ошибку, а не скрытое удаление исходного поля.

После сохранения музыка пока не изменена. Manifest хранит неизменяемые proposal IDs, входные SHA, измененные/пропущенные поля и выбранную версию релиза. Перейдите в карточки, проверьте предложения и используйте обычную запись. Ее ограниченные worker-потоки, backup, аудиоидентичность, журнал и индивидуальный rollback остаются тем же маршрутом. Этот блок не создает apply jobs автоматически, не переименовывает и не удаляет музыку.

Сохранение идемпотентно: повтор с тем же Idempotency-Key и телом возвращает тот же пакет. Другой запрос с тем же ключом получает 409. Новое изменение файла/предложения/политики после preview требует нового просмотра; старый токен не дает допуск к новой версии. CAS исключенных файлов не является разрешением их записи: они вообще не получают предложение пакета.

API owner session + CSRF:

- `GET /api/album-batches/context?ids=id1,id2` возвращает текущие SHA, proposal IDs, поля, locks и ссылки доступных cover-кандидатов. Optional `review_id`/`review_version` связывают состав с принятой сверкой.
- `POST /api/album-batches/preview`: `track_ids`, `revisions`, `base_proposals`, `tags`, optional `cover` или `cover_source:{track_id,candidate_id,input_sha256}`, `exceptions:{id:{exclude,skip_fields,tags}}`, `lock_mode`. Для эталонных полей - `release_review_id`, `release_review_version`, `release_fields`.
- `POST /api/album-batches/save`: то же тело + `preview_token`, заголовок `Idempotency-Key`.
- `GET /api/album-batches/{id}` возвращает manifest, без копирования raw lyrics/cover в отдельное хранилище. Proposal-содержимое подчиняется обычным cache/backup policy.

Данные источников, ссылки, права и field_sources из тела клиента не принимаются. Preview не сохраняет raw provider content. Общий объем новых proposal payload ограничен 256 МиБ: слишком большую обложку/группу нужно уменьшить или разделить до сохранения. Оригиналы и аудио этим API не затрагиваются.

[test_album_batch.py](../tests/test_album_batch.py) проверяет атомарность/CAS, отказ второй вставки, locks, индивидуальное исключение, сторонние lyrics sources, MIME, запрет manual laundering, стабильный preview обложки и серверный provenance релиза. Запуск на build-01 фиксируется отдельным CHECK; наличие этих тестов не является утверждением о выполненной приемке.

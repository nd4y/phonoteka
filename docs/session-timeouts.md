# Сроки сессии владельца

Cookie-сессия завершается после простоя или по абсолютному сроку. По умолчанию это 60 минут без действий пользователя и 12 часов после входа. Повторный вход создает новую сессию. API-токены имеют собственные сроки и отзыв; активность cookie их не продлевает.

| Переменная | По умолчанию | Диапазон |
| --- | --- | --- |
| `SESSION_IDLE_MINUTES` | `60` | целое число `1..1440` |
| `SESSION_ABSOLUTE_HOURS` | значение `SESSION_HOURS` | целое число `1..720` |
| `SESSION_HOURS` | `12` | прежнее имя абсолютного срока, целое число `1..720` |

Явный `SESSION_ABSOLUTE_HOURS` имеет приоритет над `SESSION_HOURS`. Неверные значения останавливают запуск конфигурации. Cookie `Max-Age` соответствует абсолютному сроку; сервер независимо проверяет оба срока при каждом запросе. Изменение настроек требует перезапуска приложения. Уменьшение сроков ограничивает существующие сессии, увеличение не оживляет истекшую сессию. Еще действующая сессия может получить новый idle-срок после следующего разрешенного действия, в пределах ее исходного абсолютного срока.

Интерфейс отправляет `POST /api/auth/activity` с `{}`, cookie, `Origin` приложения и `X-CSRF-Token` только после доверенного действия пользователя в видимой вкладке. Рекомендуемый интервал между такими запросами - 30 секунд; автоматического heartbeat нет. Фоновые GET-запросы, summary/jobs/session polling, SSE, аудио `timeupdate` и само воспроизведение не продлевают простой. При долгом прослушивании можно выбрать больший `SESSION_IDLE_MINUTES`.

Activity требует интерактивную owner-сессию. Bearer-токен не может обновить cookie-сессию. Истекшая, удаленная или отозванная сессия получает `401`; activity не создает сессию заново. Ошибки CSRF/Origin дают `403` без обновления времени. Ответы login/session/activity содержат `idle_expires_at` и `absolute_expires_at` в Unix seconds, а также `activity_interval_seconds: 30`; без действующей сессии deadlines равны `null`.

Состояние idle хранится в приватных `settings` с точным префиксом `session_activity:`: только хеш идентификатора сессии, timestamps и auth epoch, без значения cookie. Записей не больше 20, как и самих сессий. Выход удаляет соответствующую запись; выход из всех устройств и сброс пароля очищают их все. При запуске и новом входе удаляются осиротевшие/недействительные записи. Старые сессии без этих данных требуют нового входа. Общая схема SQLite остается версии 2 без изменения baseline SQL/checksum.

Работа фоновых jobs не привязана к продлению owner-cookie. Обычный выход не отзывает уже одобренный фоновой grant; сброс доступа и правила API-токенов проверяются отдельно.

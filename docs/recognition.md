# Распознавание и производные файлы

`EXTERNAL_METADATA=true` включает запросы MusicBrainz, LRCLIB и Cover Art Archive. `EXTERNAL_FINGERPRINTS=true` отдельно разрешает ShazamIO. Оба флага по умолчанию выключены. Для текущего личного экземпляра пользователь разрешил оба вида запросов 18 октября 2026 года.

ShazamIO 0.8.1 формирует отпечаток локально из фрагмента до 12 секунд, начиная с четверти записи или 45-й секунды. Передаются только signature, timestamp, timezone и пустые context/geolocation. Аудиофайл, путь и теги в этот запрос не входят. Транспорт разрешает один HTTPS-запрос к amp.shazam.com, ограничивает время и размер ответа, не следует перенаправлениям. Между запросами не менее 2 секунд, действуют общий дневной бюджет провайдера, кэш и паузы после ошибок/429. Кэш идентифицируется содержимым фрагмента; одинаковый фрагмент не расходует квоту повторно. Это неофициальная интеграция [ShazamIO](https://github.com/shazamio/ShazamIO), доступность внешнего сервиса не гарантируется.

Задание `recognize` работает для одного, выбранных или всех отдельных аудиофайлов. У найденного варианта есть `identification=audio_fingerprint`. По распознанным исполнителю и названию запрашиваются текст и релиз, даже если исходные теги отсутствуют или ошибочны. Отпечаток не подтверждает конкретное издание, мастеринг или обложку. Кандидаты становятся предложением только после выбора; запись остается отдельной операцией с резервной копией.

`replaygain` локально измеряет трек через FFmpeg ReplayGain и создает отдельный вариант с `replaygain_track_gain` и `replaygain_track_peak`. Выбор этого варианта и применение записывают только теги. Аудиосэмплы не нормализуются и не перекодируются. Это track gain; совместное измерение album gain еще не реализовано. Обычные проверки ревизий, пакетов и откат действуют для всех поддерживаемых профилей записи.

`extract_cue` создает композиции в `.phonoteka-derived/<identity>/` рабочей коллекции, сохраняя исходный CUE и образ. Целочисленное PCM до 24 бит сохраняется в FLAC; float и 32-битное PCM сохраняются в WAV без уменьшения точности декодированного сигнала. Для MP3-образа это более крупные WAV, без повторного кодирования с потерями. Каждый результат проверяется по SHA декодированных PCM до и после тегов, затем альбом целиком фиксируется атомарным переименованием нового каталога без перезаписи. Манифест хранит SHA источников, границы в сэмплах, профиль и происхождение.

Границы идут по INDEX 01. INDEX 00 остается в предыдущей композиции, звук до первого INDEX 01 сохраняется отдельным lead-in. PREGAP/POSTGAP из текста CUE не добавляют отсутствующие в файле сэмплы. Переходы между FILE проверяются отдельно. Неоднозначные ссылки, устаревшие зависимости, поврежденные источники и занятые пути дают явную ошибку. Повтор неизменного экспорта использует проверенный результат. После изменения производного файла повтор не перезаписывает его. Производные композиции появляются в каталоге и доступны обычным распознаванию, предложениям, записи и публикации.

Остановленное во время подготовки CUE задание не публикует половину альбома. После аварийного завершения процесса могут оставаться служебные данные в `.phonoteka-staging`, исключенной из сканирования; конечный каталог появляется только целиком. Завершенный каталог с манифестом можно повторно проиндексировать идемпотентным экспортом после перезапуска.

Проверка известного музыкального фрагмента установила Numb / Linkin Park / Meteora. Локальное сведение текста LRCLIB на полном треке надежно привязало 50% строк; оставшиеся строки не получили выдуманных времен. Это подтверждает работу ограничений, но не полную музыкальную точность ASR. Итоговая проверка на физическом Poweramp остается отдельной.

Для временно недоступных источников предусмотрен `scope=pending`: повторяются только незавершенные этапы для актуальных ревизий. Полученный ранее отпечаток используется повторно при поиске текста. LRCLIB сначала запрашивается по точным названию/исполнителю/альбому/длительности, затем через search при отсутствии записи. Сетевые паузы метаданных постепенно растут от 60 секунд до 20 минут; Retry-After не сокращается. Если первый отпечаток не найден, проверяется один дополнительный фрагмент ближе к концу песни в пределах того же бюджета.

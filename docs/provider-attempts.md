# Учет внешних HTTP-попыток

Каждый реальный HTTP-запрос метаданных, изображения или Shazam signature получает непрозрачный UUID до отправки. Попытка и расход общего суточного бюджета провайдера фиксируются одной короткой SQLite-транзакцией. Redirect и разрешенный повтор после явно полученного временного отказа используют новые записи и новые разрешения бюджета. Cache hit не создает HTTP-попытку.

Запись `provider_attempt:<UUID>` в settings содержит только источник, операцию, SHA-256 входной ревизии при наличии, тип хеша, UTC Unix timestamps, bounded code, числовой HTTP status и состояние. Нет URL, query, названия/исполнителя, аудио, текста песни, тела запроса/ответа, ключей или полного сообщения исключения. `file_sha256` означает фактический полный хеш входного файла. Если внешний fingerprint вызван без FileRevision, указывается `sample_sha256` декодированного фрагмента; неизвестный вход остается `unknown` с null hash.

Состояния:

| Состояние | Значение |
| --- | --- |
| reserved | Бюджет израсходован, разрешение отправки еще не зафиксировано |
| sent | Факт намерения отправки устойчиво записан непосредственно перед HTTP |
| succeeded | Получен и ограниченно прочитан допустимый ответ |
| no_match | Получен явный ответ отсутствия или пустой результат поиска |
| failed | Получен известный отказ, некорректный ответ либо запрос остановлен до отправки |
| unknown_outcome | После намерения отправки результат потерян: transport/read/overall timeout, отмена или потеря исполнителя |

Сбой между записью sent и фактической передачей также считается неизвестным. Приложение не может доказать отсутствие удаленной обработки. Расход не возвращается ни для unknown, ни при перезапуске; это консервативный учет приложения, а не подтвержденный счет сервиса.

`unknown_outcome` прекращает автоматические повторы этой операции. Он не превращается в no-match/provider-unavailable с новым скрытым запросом. Новый поиск возможен по отдельному решению владельца и продолжает использовать общий расход бюджета. ShazamIO использует прежний ограниченный SignatureTransport вместо собственных многочисленных HTTP retry; транспорт также проходит через общий durable ledger. Поздний ответ не перезаписывает уже признанный unknown исход.

В закрепленной [ShazamIO 0.8.1](https://github.com/shazamio/ShazamIO/blob/0.8.1/shazamio/api.py) переданный `http_client` заменяет стандартный клиент с 20 повторами; `recognize` передает signature в единственный `http_client.request`. Это дополнительно проверяется regression тестом настоящего библиотечного пути с синтетическим звуком и mock transport.

API и сетевые вызовы не держат SQLite-транзакцию во время HTTP. Число соединений ограничено, rate admission выполняется после получения слота, logical metadata deadline равен 90 секундам, fingerprint deadline - 50 секундам. Reserved/sent старше 180 секунд worker отмечает unknown без повторной отправки. Момент sent является консервативной границей учета, а не доказательством приема получателем.

Один провайдер выполняет не больше одного HTTP-запроса одновременно; его ожидающие запросы не занимают общие слоты других источников. Следующий интервал отсчитывается после полного ответа или ошибки, поэтому задержка SQLite перед отправкой не превращает ранее допущенные запросы в пачку одновременных отправок. Этот консервативный профиль сознательно снижает максимальную скорость медленного источника.

История ограничена 30 днями и 100 000 записями. При достижении count cap могут удаляться только terminal записи за пределами текущего 24-часового бюджетного окна. Unfinished записи сначала требуют сверки deadline, затем сохраняют terminal unknown исход; их содержимое не удаляется ради принятия нового HTTP. Если емкость нельзя безопасно освободить, новый вызов получает `attempt_ledger_full` до отправки. Независимый provider_calls продолжает контролировать расход текущих 24 часов.

Защищенный read-only отчет:

```text
GET /api/reports/provider-attempts?provider=shazam&state=unknown_outcome&page=1&page_size=50
```

Фильтры и page size проверяются, максимум 100 строк. Ответ не возвращает внутренний executor ID или номер строки бюджета. Тот же контракт доступен под `/api/v1`. GET ничего не отправляет и не повторяет. Unit/regression проверки используют MockTransport и синтетический собственный звук, включая 20 параллельных файлов с остатком бюджета два вызова, timeout и новый процесс клиента.

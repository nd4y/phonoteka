## PWA и оставшиеся проверки

Актуальная оболочка/manifest/icons/service worker и отказ приватным анонимным запросам проверены серверными gates CHECK-042. В Edge видны подключенный manifest и `viewport-fit=cover`, кнопка установки корректно показывает инструкцию, когда браузер не предоставляет автоматический install prompt. JavaScript-ошибок при этом не было.

**Фактический standalone launch подтвержден владельцем:** после установки штатным меню Edge он ответил «Открылась отдельным приложением». Это прямой результат пользовательской проверки, а не автоматический снимок native-окна. Показ инструкции сам по себе не считался установкой.

Предшествующую попытку прочитать список установленных приложений `edge://apps/` заблокировала URL-политика браузерного инструмента, разрешающая только HTTP/HTTPS. Обходов/другого механизма управления не применялось. После установки прежняя browser-вкладка перестала числиться в доступном списке; повторный снимок через ее старый handle не получен. Новое native-окно не объявляется автоматически проверенным. Временный viewport override сброшен документированным API.

В текущем браузерном инструменте нет документированного offline-переключателя. Поэтому реальный offline/reconnect, установленная PWA на Android и физический Poweramp остаются отдельными проверками. Logout/expiry/cache изоляция имеют серверные и автоматические регрессии текущего выпуска; реальный logout в используемом владельцем Edge-сеансе в этом протоколе не выполнялся. Принятые черновики/музыка, новые провайдеры и массовая обработка не затрагивались.

Протокол наблюдений и снимки сохранены вне Git в `output/music-library`: `browser-acceptance-e59a215-20261022.json`, `production-review-mobile-e59a215.png`. После UI-теста read-only status подтвердил все три текущих контейнера healthy, restart 0, OOM false. Полная готовность продукта по-прежнему оценивается в [production-readiness.md](production-readiness.md); положительная браузерная проверка не принимает музыкальные таймкоды.

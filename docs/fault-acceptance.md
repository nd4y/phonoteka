# Матрица отказов и границы приемки

Файл tests/test_fault_acceptance.py использует только временные каталоги и синтезированные FLAC. Внешние провайдеры и коллекция владельца не участвуют. Каждый сценарий проверяет наблюдаемое содержимое файлов, читаемость, доступность before-version, журнал и историю, а не совпадение результата с внутренним алгоритмом. Наличие этих сценариев не означает, что удаленный прогон уже завершен.

| AC | Сценарий | Инвариант |
| --- | --- | --- |
| 10, 11, 66 | Отказ backup copy, fsync staging, сбой после prepared journal, rename до и после эффекта, directory fsync | Исходник неизменен; work остается читаемым с тем же аудиосодержимым; доступный backup не удален; success не выдан |
| 10, 66 | Повторный sync error при reconciliation | Journal остается незавершенным; после снятия ошибки hash after допускает только фиксацию уже совершенного эффекта, hash before требует нового одобрения |
| 10, 11 | Потерян target при наличии before-backup; затем внешняя новая ревизия | Recovery возвращает доказанную before-version без применения старого предложения; внешняя ревизия получает conflict и сохраняется |
| 11, 66 | Две настоящие записи FLAC на одном storage domain с местом только на одну | Первая удерживает общий reserve до commit, вторая отказывает до изменения файла; reserve освобожден после завершения |
| 24 | Два apply и rollback одной исходной ревизии в очереди | Один CAS-победитель; остальные conflict, история и читаемые резервные версии сохраняются |
| 10, 66 | SQLite commit I/O failure после атомарной замены work | Job interrupted, история не заявляет успех; restart согласует уже измененный файл ровно один раз без повторной записи аудио |
| 28 | Две настоящие параллельные записи, shutdown перед commit и конкурентный writer | Старый writer удерживает guard до завершения исполнителей; после stop эффекты не происходят, оба журнала требуют нового одобрения |
| 28 | Pause при двух in-flight из трех файлов, затем resume | Критические операции завершаются согласованно, третий файл ждет; resume не повторяет первые два эффекта |
| 67 | Старый state snapshot при более новых work/Ready и потерянном rollback blob | Recovery блокирует запись, Ready показывает conflict, unavailable rollback не предлагается, фактические новые файлы не заменяются |
| 71 | Две точные копии, перенос одной, изменение байтов с прежними size/mtime, частичный и недоступный root | Истории и ручные locks не сливаются; полный hash находит изменение; partial scan не помечает невидимые файлы удаленными |

Проверки имеют ограниченные ожидания на события: до 10 секунд на барьер и до 15 секунд на завершение worker. Тяжелые тесты и сборки выполняются на build-01. Это единичные контролируемые I/O-отказы и завершение процесса приложения, не имитация отказа питания дискового контроллера.

Отдельно остаются приемка реальных SMB/NFS mount, поведения NAS/контроллера при потере питания, независимого backup после отказа NAS, передачи storage ownership между настоящими контейнерами и сетевого разделения. Локальный POSIX flock/rename/fsync сам по себе не доказывает эти свойства другой файловой системы. Для утверждения о конкретной установке нужны ее mount/volume параметры, идентичность storage domain и контролируемый инфраструктурный тест. Функциональные проверки Poweramp/Android, PWA на устройстве и музыкальный пилот ASR к этой матрице не относятся.

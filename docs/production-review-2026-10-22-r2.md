# Повторное ревью эксплуатации

Дата: 22-23.10.2026. Объем: существующие сценарии Фонотеки, без новых интеграций.

Критерии выпуска: воспроизведенные дефекты исправлены; проверены повторные
запросы, выборка незавершенных файлов, авторизация, отмена и очередь; пройдены
build-01 и полный GitHub CI для точной версии; перед обновлением проверены
состояние очередей и резервная копия; после обновления проверены установленная
версия, HTTPS, метрики и логи. Музыкальная приемка и Poweramp остаются отдельными
условиями окончательной приемки владельцем.

## Находки

- P1: запрос с прежним Idempotency-Key после окончания `scope=pending` возвращал
  `nothing_to_process`, хотя исходная задача уже существовала. Повтор теперь
  разрешается по исходному ключу до изменяемой выборки. Проверка авторизации и
  привязка ключа к пользователю/токену сохранены, повторное создание защищено
  транзакцией. Новое содержимое с прежним ключом вызывает конфликт.
- P1: лимит 10 000 применялся до исключения уже обработанных записей. Остаток
  большой коллекции никогда не попадал в последующие задания. Теперь записи
  читаются последовательно, лимит применяется к отобранным файлам. Запросы
  YouTube больше не читают метаданные каждой записи отдельным SQL-запросом.
- P2: мастер проверял только первую страницу истории задач. Старую активную
  или приостановленную задачу могли скрыть 50 новых. Перед запуском мастер
  отдельно проверяет активные задачи нужного вида и открывает обработку, если
  такая задача уже существует. Ошибка этой проверки не запускает новое задание.
  Основной экран запрашивает активные задачи первыми, чтобы старую задачу можно
  было увидеть и отменить; обычный порядок API по времени сохраняется по умолчанию.
- P2: CI мог потратить весь лимит задания на зависшую загрузку кодеков с
  системного зеркала, не дойдя до тестов. Установка выделена в отдельный этап
  с ограничением времени и сетевыми таймаутами/повторами; необязательные
  рекомендуемые пакеты не устанавливаются. Подписи пакетов и все тесты сохранены.

## Проверки

Два первых дефекта воспроизведены отдельными тестами на исходной версии:
оба теста получили ошибку 409 вместо ожидаемого результата. Использованы только
синтетические данные; реальные файлы и внешние музыкальные сервисы не затронуты.
Третий регрессионный сценарий проверяет старую приостановленную задачу за
51 новой завершенной записью: активная выборка находит ее, основной экран
показывает первой, обычная хронология API сохраняется.

На build-01 прошли 137 целевых backend-тестов, затем весь backend:
616 тестов и 60 подтестов. Frontend: 210 тестов в 33 файлах, TypeScript,
production/PWA build и npm audit без находок. Запуски ограничены ресурсами
и общим lock; чужие задания и VM не менялись.

[GitHub CI 39848401175](https://github.com/nd4y/phonoteka/actions/runs/39848401175)
для `d897c364b35f56267345ff01a0debeb01fa6f41a` прошел все четыре задания:
616 backend / 210 frontend, проверку 62 установленных модулей по Git,
19 ASR / 7 combined / 15 ordinary критериев. Последнее изменение касалось
только установки кодеков в CI; runtime и тесты побайтово совпадают с проверенными
на build-01 исходниками. Реальные модельные проверки на синтетических данных
не являются независимой оценкой музыкальных таймкодов.

Edge на изолированном демо подтвердил поиск старой задачи через мастер без
дубликата, ее отображение и отмену, Back и немедленный F5. При ширине 390 px
горизонтального переполнения нет, ошибок консоли нет. Синтетические записи задач
убраны после проверки. UI/PWA-файлы фактического CI-образа побайтово совпали
с проверенной браузером сборкой. Предыдущий протокол controlled-origin outage,
reconnect и logout остается отдельным доказательством; физический offline
Android не объявлен проверенным.

Предположение внешнего read-only ревью о `waiting_storage` как отдельном
серверном состоянии не подтвердилось: worker хранит `queued` и соответствующий
этап, которые мастер уже учитывает. Исправление по этому предположению не вносилось.

## Выпуск и границы приемки

Выпуск `d897c364b35f56267345ff01a0debeb01fa6f41a` установлен и проверен
23.10.2026 по московскому времени. Перед обновлением проверены очереди и
создана свежая приватная копия состояния. Изменены только образы приложения,
worker и inference; схема, настройки и доступ к медиа сохранены. Старые образы
и checkpoint оставлены для отката. Обновление не возобновляло обработку коллекции.

Все три сервиса healthy, restart 0 / OOM false. Пройдены 42 target и 19 origin
проверок, включая HTTPS, owner login/logout, CSRF/origin, запрет анонимного
доступа к каталогу и аудио, Range-запрос и защиту оригиналов от записи.
Метрики всех компонентов требуют токен, логи представлены JSON в stdout;
в проверенной выборке нет утечек секретов. Все 63 запроса Grafana прошли.
Операционные протоколы и детали восстановления хранятся отдельно от репозитория.

Критерии этого исправляющего выпуска выполнены. Полная приемка продукта и
организации коллекции остается открытой: физический Poweramp и независимая
проверка слов/таймкодов отложены владельцем; нерешенные совпадения и поврежденные
файлы не объявлены исправленными. Новые функции не добавлены.

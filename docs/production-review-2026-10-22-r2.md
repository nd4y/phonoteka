# Повторное ревью эксплуатации

Дата: 22.10.2026. Объем: существующие сценарии Фонотеки, без новых интеграций.

Критерии выпуска: воспроизведенные дефекты исправлены; проверены повторные
запросы, выборка незавершенных файлов, авторизация, отмена и очередь; пройдены
build-01 и полный GitHub CI для точной версии; перед обновлением проверены
состояние очередей и резервная копия; после обновления проверены установленная
версия, HTTPS, метрики и логи. Музыкальная приемка и Poweramp остаются отдельными
условиями окончательной приемки владельцем.

## Находки

- P1: запрос с прежним Idempotency-Key после окончания `scope=pending` возвращал
  `nothing_to_process`, хотя исходная задача уже существовала. Повтор теперь
  разрешается по исходному ключу до изменяемой выборки. Проверка авторизации и
  привязка ключа к пользователю/токену сохранены, повторное создание защищено
  транзакцией. Новое содержимое с прежним ключом вызывает конфликт.
- P1: лимит 10 000 применялся до исключения уже обработанных записей. Остаток
  большой коллекции никогда не попадал в последующие задания. Теперь записи
  читаются последовательно, лимит применяется к отобранным файлам. Запросы
  YouTube больше не читают метаданные каждой записи отдельным SQL-запросом.
- P2: мастер проверял только первую страницу истории задач. Старую активную
  или приостановленную задачу могли скрыть 50 новых. Перед запуском мастер
  отдельно проверяет активные задачи нужного вида и открывает обработку, если
  такая задача уже существует. Ошибка этой проверки не запускает новое задание.
  Основной экран запрашивает активные задачи первыми, чтобы старую задачу можно
  было увидеть и отменить; обычный порядок API по времени сохраняется по умолчанию.
- P2: CI мог потратить весь лимит задания на зависшую загрузку кодеков с
  системного зеркала, не дойдя до тестов. Установка выделена в отдельный этап
  с ограничением времени и сетевыми таймаутами/повторами; необязательные
  рекомендуемые пакеты не устанавливаются. Подписи пакетов и все тесты сохранены.

## Проверки

Два первых дефекта воспроизведены отдельными тестами на исходной версии:
оба теста получили ошибку 409 вместо ожидаемого результата. Использованы только
синтетические данные; реальные файлы и внешние музыкальные сервисы не затронуты.
Итоговые результаты и установленная версия будут записаны после завершения
проверок и доставки.

Предположение внешнего read-only ревью о `waiting_storage` как отдельном
серверном состоянии не подтвердилось: worker хранит `queued` и соответствующий
этап, которые мастер уже учитывает. Исправление по этому предположению не вносилось.

## Архитектура и границы

Фонотека декодирует замороженную копию файла на NAS в ограниченный mono/16 kHz
PCM и обращается к существующему независимому recap-asr на PC2 через HTTPS
внутреннего прокси. Прокси использует существующий LAN HTTP-слушатель PC2;
TLS завершается на прокси. Новый маршрут ограничен собственным hostname и
`/v1/whisper/`. Остальные маршруты и сетевые ACL не менялись.

На PC2 добавлены только общие модельные маршруты существующего ASR-движка.
Исходники Фонотеки, база, конфигурация приложения и его секреты не передавались.
Large-v3 float16 закреплен на ревизии
`edaa852ec7e145841d8ffdb056a99866b5f0a478`; проверен SHA модели.
Политика независимых опор, сопоставление строк и запрет автоматического
принятия остаются в Фонотеке. Прежний GigaAM endpoint проверен реальным
60-секундным фрагментом: успешно, 20,094 с, 32 слова.

Отдельный ключ смонтирован только в inference, read-only, UID1026/mode0400.
Нормальная проверка TLS включена; неподписанный запрос получает401.
Локальные модельные веса на NAS не загружаются. Дочерний клиент ограничен
512 МиБ; недоступность PC2 не запускает скрытый CPU fallback.
Существующие сервис и GPU lock последовательно обслуживают модельные запросы,
а чужая GPU-нагрузка не завершается ради освобождения памяти.

## OOM и отмена

Обнаружен разрыв прежних ограничений: supervisor мог допускать2ГиБ при CI cap
1280МиБ. Теперь CPU-профиль требует3ГиБ до загрузки весов; эффективный RSS
дополнительно ограничен cgroup v1/v2 cap с резервом256МиБ. MKL packed GEMM
отключен. A/B на build-01 при одинаковом успешном распознавании дал пики
820/636МиБ; исходный GitHub OOM целиком не воспроизведен, это ограничение
диагностики сохранено. Новый CI отдельно проверил ранний отказ1280МиБ без
загрузки модели и прошел реальные ASR-проверки в объявленном3ГиБ профиле.

Отмена inference атомарно проходит cancelling -> cancelled и не принимает
поздний результат. Исправлены повторная ASGI-cancellation, потеря HTTP disconnect
через middleware и Windows venv launcher: завершается собственное дерево
модельного процесса, затем удаляется scratch и освобождается lock.
Живая проверка через HTTPS наблюдала работающий GPU child, отключила клиента
и получила cleanup за0,922с, cancelled+1, без успешного результата;
active/inflight вернулись0. Чужие процессы и VM не перезапускались.

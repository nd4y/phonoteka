## Поведение

Отчет начинается с количества аудиофайлов и трех независимых показателей: основные теги (название, исполнитель, альбом), встроенная обложка и синхронный текст. У каждого есть число, знаменатель и процент. CUE исключен из знаменателя. Наличие данных не означает правильность, общего процента готовности нет.

Отдельные карточки показывают ошибки проверки аудио, сохраненные предложения и публикации текущей версии. Варианты источника не выдаются за пользовательские предложения. Прошлая SHA-ревизия не считается текущим анализом, предложением или публикацией. Ошибка проверки не называется доказанным повреждением. Кнопки открывают существующие фильтры без старого поискового запроса. Технические результаты, YouTube и экспорт свернуты в объясненные подробности. У снимка есть время; при ошибке обновления предыдущий снимок явно помечен.

Мастер: папка -> каталог -> аудиоотпечаток -> метаданные -> проверка/запись -> публикация. Используются существующие настройки и guarded API. Открытие или F5 не создают задач; незавершенные этапы запускаются явно. Paused/waiting/deferred задачи используются повторно. ASR, запись, публикация и подключение нового источника не запускаются автоматически. Справка объясняет различия между предложением, файлом и Ready, CUE, ASR, источники, отмену, ETA и PWA.

Шаги мастера включены в общую историю. «Мастер -> справка -> мастер -> Назад» возвращает к справке; следующий возврат - к прежнему шагу. Это проверено после reload. F5 сразу после Back сохраняет целевой экран/позицию, даже пока идет восстановление содержимого. Logout очищает состояние мастера вместе с приватной навигацией.

## PWA и logout

Исправлен public root-navigation fallback: раньше fetch.catch работал при network exception, но не при HTTP502 от proxy. Теперь network exception/5xx возвращают только precached public index. HTTP401/403/404 и приватные API/audio не маскируются и не кэшируются; runtime responses в cache не записываются. Worker tests покрывают эти различия и отсутствие shell.

В Edge остановлен только точный CID собственного синтетического демо, production работал. F5 показал сохраненный интерфейс, ошибку502 и «Повторить», без каталога/audio DOM. Демо восстановлено; «Повторить» вернула прежний шаг распознавания и действующий сеанс. Это контролируемая недоступность origin через proxy; физическое отключение сети телефона или navigator-offline переключатель браузера не проверялись.

Logout: перед выходом реально играл WAV (readyState4/paused=false/no media error). После завершения запроса login, audio DOM=0, private app-shell отсутствует. Browser Back и F5 сохранили login. Первая попытка повторного входа остановилась на timeout инструмента до dispatch. После стандартного входа в свежей Edge-вкладке следующая вкладка того же origin открыла каталог и отчет с новым сеансом, без старого плеера. В первой вкладке окно расширения Edge блокировало автоматизацию после входа; свежая вкладка того же origin успешно использовала действующий сеанс. Права/пароли production не менялись.

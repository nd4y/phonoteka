# Необязательные webhook уведомления

По умолчанию webhook выключен. Исходники и тесты не задают реального получателя и не отправляют пользовательские данные наружу. Оператор включает интеграцию в Docker-конфигурации, а владелец может приостановить доставку, продолжить ее и повторить окончательно не доставленное уведомление. Интерфейс не принимает новый URL или секрет из тегов, кандидатов, HTTP payload или формы настроек.

Параметры приложения:

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `WEBHOOK_ENABLED` | `false` | Явное включение оператором |
| `WEBHOOK_URL` | пусто | Полный HTTPS URL получателя, порт 443, без userinfo/query/fragment |
| `WEBHOOK_ALLOWED_HOSTS` | пусто | Точные имена разрешенных хостов через запятую, без wildcard |
| `WEBHOOK_SECRET_FILE` | не задан | Файл HMAC-секрета длиной от 32 байт, смонтированный read-only; секрет не хранится в UI/БД |
| `WEBHOOK_ALLOW_PRIVATE` | `false` | Отдельный выбор оператора для разрешенного частного сетевого получателя |
| `WEBHOOK_MAX_PENDING` | `10000` | Лимит ожидающих/доставляемых уведомлений вместе с резервами активных задач |

Конкретные адреса, ключи и mounts задаются отдельным deployment override. Нет автоматической регистрации endpoint и автоматического разрешения частных адресов. Loopback, link-local, cloud metadata, multicast, unspecified и reserved addresses запрещены даже при `WEBHOOK_ALLOW_PRIVATE=true`. Все адреса DNS-ответа проверяются. Запрос идет на выбранный проверенный IP с исходными Host и TLS SNI; повторное разрешение имени не может перенаправить его на NAS или metadata. HTTP proxy из переменных окружения не используется, TLS-проверка не отключается, redirects запрещены. Использован документированный [HTTPX sni_hostname extension](https://www.python-httpx.org/advanced/extensions/#sni_hostname).

Подписка включает только окончательные результаты задач: `job_finished`, в том числе ошибка и отмена до старта. Текущие действия по файлам доступны в SSE и не размножаются в webhook. Payload содержит стабильные event/job ID, тип операции, терминальный статус, числовые счетчики и разрешенный код ошибки. В нем нет названий треков, путей, аудио, lyrics, полных сообщений провайдера, учетных данных или содержимого stdout.

Контракт этой версии - одно терминальное уведомление на принятую задачу. После аварии результат `interrupted` может позднее измениться на `succeeded`, когда recovery сверит журнал и уже выполненный эффект. Второе уведомление для той же задачи не создается. Поэтому webhook фиксирует исход попытки в указанный момент и служит сигналом перечитать актуальное состояние через `GET /api/jobs/{job_id}`; текущий результат и последующие recovery-события доступны в API/SSE. Нельзя считать доставленный ранее `interrupted` неизменяемым окончательным состоянием каталога.

Запись outbox создается в той же SQLite-транзакции, что событие результата. До принятия новой задачи резервируется место для ее окончательного уведомления. Поэтому полный outbox не мешает уже принятой задаче сохранить музыкальный результат. Если лимит занят, новый POST возвращает `503 webhook_queue_full` до принятия операции, а расписание откладывает запуск. После доставки место освобождается. Выключение webhook во время уже принятой задачи сохраняет ее зарезервированное уведомление для следующего включения, но не отправляет его наружу.

Доставка имеет семантику **at least once**. Сбой после приема запроса получателем и до записи подтверждения может привести к повтору. Стабильный ID имеет вид `notification_epoch_uuid:event_row_id`; он не меняется при retry, restart или явном повторе dead letter. Restore меняет epoch только для новых уведомлений, чтобы новая история после старого снимка не столкнулась с уже принятыми ID. Существующие записи сохраняют исходный ID. Получатель обязан сохранять обработанные ID и не повторять свой эффект для того же ID. Уведомление не ставит музыкальную задачу повторно.

Заголовки:

- `X-Phonoteka-Event-ID` и `Idempotency-Key`: стабильный ID уведомления.
- `X-Phonoteka-Timestamp`: целое Unix-время попытки.
- `X-Phonoteka-Signature`: `sha256=<hex HMAC-SHA256>`.

Подписываются байты `timestamp + "." + event_id + "." + raw_body` в UTF-8. Получатель сравнивает HMAC constant time, проверяет совпадение header ID с body ID, отклоняет время за пределами окна 300 секунд и выполняет дедупликацию по ID. В модуле есть `verify_signature` для проверки HMAC и окна; хранилище дедупликации получателя остается обязанностью получателя. Парсинг и повторная сериализация JSON перед проверкой подписи недопустимы.

Отправитель не читает тело ответа. Любой 2xx подтверждает доставку; redirects и постоянные 4xx дают видимый окончательный отказ. 408, 425, 429, 5xx и сетевые/неизвестные исходы повторяются с backoff, максимум восемь попыток, без возврата уже учтенных попыток после crash. Общий сетевой deadline 10 секунд; DNS имеет отдельный трехсекундный предел. Захват записи использует короткую транзакцию, lease и CAS token; просроченный отправитель не перезаписывает результат нового lease.

Только terminal delivered/dead записи удаляются автоматически по сроку семь дней и лимиту 5000. Pending/in-flight и резервы не удаляются по TTL. Смена URL создает другой destination ID; прежние уведомления не перенаправляются новому получателю. Статус показывает такие записи отдельно. Restore включает recovery mode и приостанавливает webhook до проверки и явного продолжения владельцем.

Защищенные API:

- `GET /api/webhooks?page=1&page_size=30`: счетчики, безопасная конфигурация и ограниченная страница статусов без URL path/секрета/body.
- `POST /api/webhooks/pause` и `/resume`: управление доставкой, owner session + CSRF.
- `POST /api/webhooks/{event_id}/retry`: повтор dead letter с тем же ID после проверки текущего получателя и емкости.

Все маршруты также доступны под `/api/v1`. Логи содержат только ID, состояние, число попыток и ограниченный код исхода. Наличие кода и mock-тестов не означает, что внешний получатель настроен или проверен в реальной эксплуатации.

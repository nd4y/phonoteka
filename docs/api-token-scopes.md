# Области доступа API-токенов

Владелец выдает токен в разделе «Автоматизация и API». Значение показывается один раз; сервер хранит хеш, название, срок и last used. Передавайте его только в `Authorization: Bearer`, не в URL. Токен не заменяет интерактивный вход для настроек, выдачи токенов или личных подтверждений прослушивания и Poweramp.

| Scope | Разрешает | Сам по себе не разрешает |
| --- | --- | --- |
| `library:read` | Читать коллекцию, медиа, задачи, отчеты и готовые снимки экспорта | Создавать или изменять задачи, предложения и публикации |
| `jobs:create` | Создавать задачи анализа, аудита и сканирования; управлять разрешенными задачами | Записывать Work, создавать производные или публиковать Ready |
| `files:write` | Готовить и редактировать предложения, выбирать результат анализа | Публиковать Ready; создавать файловую задачу без `jobs:create` |
| `publish:write` | Готовить планы публикации, управлять арендой экспорта и сообщать о доставке | Изменять или откатывать Work; создавать задачу без `jobs:create` |

Для `apply`, отката Work, извлечения CUE и создания нормализованной производной нужны одновременно `jobs:create` и `files:write`. Для публикации, экспорта Ready и относящихся к Ready задач нужны `jobs:create` и `publish:write`. Дополнительные серверные требования к принятой ревизии, сохраненному плану и явному owner-подтверждению остаются в силе. Область доступа не заменяет проверку прав источника, состояния файла или музыкальной приемки.

Обычная интеграция анализа получает `library:read` и `jobs:create`. Интеграции записи Work добавляют `files:write`, а публикации - отдельно `publish:write`. Можно выдать токен только для одной области: сервер не добавляет чтение или создание задач автоматически. Вызовы создания задач используют `Idempotency-Key`; текущая ревизия и планы проверяются как при интерактивной работе.

В принятой задаче сохраняются инициатор и снимок разрешений. Перед следующими эффектами worker проверяет и этот grant, и действующие scopes/expiry/revocation/auth epoch токена. Новые права токена не расширяют старый grant. Возобновление задачи с явным новым одобрением сохраняет ее работу, но связывает оставшиеся эффекты с новым grant. Уже начавшаяся согласованная файловая операция завершается безопасно; отзыв не считается откатом отправленного запроса.

## Совместимость прежних токенов

Прежние имена поддерживаются без изменения сохраненного токена:

- `read` сохраняет прежнее чтение и соответствует `library:read`.
- `jobs:analysis` сохраняет прежний набор задач анализа, включая исторически доступный `export_ready`. Это исключение для указанного задания, а не общее право публикации, доставки, записи Work или ручного редактирования предложений.
- `jobs:write` сохраняет прежние задачи записи/отката/публикации/производных и связанные разрешенные API-операции. Он не приобретает чтение или задачи анализа. Прежние owner-only ограничения также сохраняются.

Для новых интеграций используйте четыре явно выбранные области. Не переводите прежний `jobs:analysis` в широкий `publish:write` только ради совместимости. Существующие фоновые задачи без снимка scopes проверяются только по прежним именам; автоматического повышения прав или изменения payload старых задач нет.

# Квота запросов и паузы источников

`PROVIDER_DAILY_LIMIT` - локальная квота Фонотеки на каждый источник за скользящие 24 часа. Это не лимит API и не блокировка IP. По умолчанию она равна 2500; `0` отключает суточную квоту. Отрицательное значение отклоняется. После изменения переменной обновите стек приложения и worker через штатный процесс выпуска. Возврат положительного значения сразу учитывает сохранённые запросы текущего окна.

При отключении квоты сохраняются кэш, журнал каждой попытки, ограничение параллелизма и скорости, запрет автоматического повтора отправленного запроса с неизвестным исходом и бюджет распознавания одной аудиозаписи. Счётчики не сбрасываются, существующие задания не пересоздаются.

LRCLIB опрашивается последовательно с паузой не менее секунды после ответа. Ответы 429 и 503 задают общую паузу источника по `Retry-After` (число секунд или HTTP-дата), с небольшим случайным добавлением. Ожидающие запросы проверяют эту паузу перед отправкой. При необходимости увеличить реальные лимиты LRCLIB предлагает регистрацию приложения: [официальные требования](https://lrclib.net/docs.txt). Смена IP не влияет на локальную квоту Фонотеки.

В настройках источников отключённая квота подписана явно. API `/api/providers` возвращает `daily_limit: 0` и `daily_limit_enabled: false`. Метрика `phonoteka_provider_daily_limit_enabled` равна 0, а `phonoteka_provider_budget_remaining` - `+Inf`; счётчик `phonoteka_provider_requests_24h` продолжает отражать расход. Это не обещание отсутствия ограничений внешнего сервиса.

Тест общего срока чтения ответа завершает настоящий таймер после первого фрагмента ответа. Он проверяет закрытие потока, неизвестный исход и ровно один учтённый запрос, не требуя завершить подготовку в SQLite за 200 мс. Рабочие таймауты приложения не меняются.

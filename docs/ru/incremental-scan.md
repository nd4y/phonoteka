# Сканирование изменений

В коллекции основное действие - **Сканировать изменения**. Оно по-прежнему
обнаруживает файлы в выбранном рабочем каталоге, но целиком читает только новые,
изменившиеся, ошибочные и ещё не подтверждённые записи. Для новой записи нужны
два завершённых независимых чтения и прежний период стабильности. Один просмотр
атрибутов не заменяет второй проход.

Прежний успешный результат используется, только если совпадают размер, время
изменения и сохранённая версия; изменение ctime, устройства или inode также
требует чтения. Для старых записей без сохранённого inode дополнительно
проверяется, не менялись ли родительские каталоги после полного чтения.
Перед завершением пропуски проверяются ещё раз: изменение во время работы
возвращает файл в текущую проверку. Это оптимизация обнаружения изменений, а не
новое подтверждение содержимого: дата SHA-256 и прежние доказательства
стабильности пропущенных файлов остаются прежними. Проверка SHA перед записью
в аудио сохраняется.

Названия файлов и атрибуты всё равно читаются для обнаружения новых и отсутствующих
путей; для записей без расширения существующее обнаружение читает короткий
заголовок. CUE повторно проверяется вместе со ссылками на аудио: неизменившийся
документ может ссылаться на исчезнувший или заменённый файл. Ошибочные файлы
остаются видимыми и проверяются при следующем запуске.

В **Действия с коллекцией → Полное сканирование** можно принудительно заново
прочитать все файлы и сверить SHA-256, в том числе после восстановления файловой
системы или при недоверии к её атрибутам. Полная сверка подключения рабочего
каталога остаётся отдельной административной операцией.

В обработке показаны обнаруженные файлы, число записей без повторного чтения
и фактические попытки проверки. Пропуски не добавляются к выполненным попыткам
и не создают отдельные записи журнала для каждого неизменившегося файла. Если
работы нет, задача завершается с сообщением об отсутствии изменений.

Проверка не принимает теги или текст, не публикует аудио и не вызывает музыкальные
сервисы. Отмена и ошибка перечисления не создают новое подтверждение стабильности
и не помечают невидимые пути отсутствующими. Уже принятые задачи без нового
параметра сохраняют полное сканирование; ограниченные два прохода подготовки
данных также сохраняют свой замороженный состав.

API новых обычных задач фиксирует `scan_mode: incremental` по умолчанию;
`scan_mode: full` включает полное чтение. Другие типы задач и административная
сверка не принимают этот параметр. Приёмка кода, build-01, GitHub, выкладки
и установленного UI подтверждается отдельно в карточке изменения.

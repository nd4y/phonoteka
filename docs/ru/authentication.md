## Режим без входа

`AUTH_ENABLED=true` включен по умолчанию. Для экземпляра с доступом, ограниченным на уровне сети или reverse proxy, администратор может явно задать `AUTH_ENABLED=false` в конфигурации Docker и пересоздать приложение. Каждый, кто может открыть адрес, получает полный доступ к коллекции и настройкам, включая запись файлов. Это не гостевой режим. В UI отображается «Вход отключен», кнопки выхода скрыты; переключателя в браузере нет.

Защита изменяющих запросов сохраняется: нужен точный `Origin`, равный `APP_URL`, и `X-CSRF-Token` из `/api/auth/session`. Приложение не создает анонимные cookie или постоянные сеансы. API-запросы с Bearer продолжают проверять токен и его области доступа; метрики и inference используют прежние отдельные ключи. Режим не меняет разрешения внешних провайдеров, ограничения записи, проверку публикации и очередь.

В режиме без входа после перезапуска сервера открытая вкладка получает новый CSRF-токен, если сервер явно отклонил запись по устаревшему токену. Интерфейс повторяет один и тот же запрос один раз с сохранением идентификатора и проверки ревизии.

Для возврата защиты установите `AUTH_ENABLED=true` и пересоздайте приложение. Пароль и существующие учетные данные сохраняются; на первом защищенном запуске по-прежнему нужен `OWNER_PASSWORD_FILE`. Значения, кроме `true`, `false`, `1`, `0`, отклоняются при запуске. При смене режима обновите вкладку, чтобы получить актуальное состояние входа.

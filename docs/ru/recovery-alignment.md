# Восстановление очереди и текст для ASR

В разделе «Источники» откройте действия с таймкодами, содержимым аудио и громкостью. Если автоматическое определение ошиблось, выберите «Язык записи» перед повторной проверкой содержимого или сведением текста с аудио.

ASR использует длительность декодированных отсчётов для распознавания и выравнивания. У MP3 с одним аудиопотоком оценка по заголовку или битрейту может быть неверной; результат сохраняет обе длительности в `duration_evidence`. Существенное расхождение в других контейнерах или при нескольких потоках остаётся ошибкой. Декодер допускает одну контрольную секунду сверх лимита профиля, затем отклоняет избыток отсчётов до загрузки в память и обращения к PC2. Обрезанный до 30 минут результат не принимается как полный. Предварительный отказ при заявленной длительности больше 30 минут сохраняется. Байты исходника, модель, пороги уверенности и правила принятия результата не меняются.

Если обработчик остановился во время анализа метаданных, распознавания, проверки аудио, ASR, выравнивания, ReplayGain или поиска источника YouTube, при запуске задание переходит в состояние «Приостановлено». В «Обработке» нажмите «Продолжить». Уже завершённые элементы не выполняются повторно; прерванные элементы больше не отображаются как работающие. Запрошенная до сбоя отмена сохраняется. Счётчики провайдеров и неопределённые результаты запросов не сбрасываются.

Это восстановление не публикует файлы и не возобновляет сетевые запросы само. Для операций записи продолжает действовать сверка файлов и журналов; она не заменяется повтором задания.

При ошибке декодирования аудит сохраняет уже проверенный список аудиопотоков: это позволяет оценить восстановление FLAC с одним потоком. Повреждённая встроенная обложка не блокирует создание проверенной производной аудиокопии. Обложка остаётся в сохранённом исходнике, а манифест производного файла явно отмечает её пропуск. Утраченные аудиоданные и изображения не выдумываются.

Признак обложки проверяет выбранное для воспроизведения изображение тем же ограниченным декодером JPEG/PNG, что используется при импорте. HTML со страницей ошибки или неподдерживаемый формат, например GIF, означает отсутствие пригодной обложки и предупреждение `artwork_warning=invalid_cover`. Байты и остальные слоты изображений сохраняются. Для обновления старых записей повторите сканирование; затем анализ метаданных сможет искать замену. Такая проверка сама не меняет формат изображения и не подтверждает предложенную обложку.

Выравнивание использует только текст и связанные с ним ограничения источника. Просроченные предложения тегов или обложек не блокируют ASR текста. Для уже записанного в файл разрешённого текста срок HTTP-кэша не является сроком жизни файла. Отозванное разрешение и ограничения исходного текста продолжают проверяться перед постановкой и исполнением задания. Для ещё не записанного предложения текста срок кэша сохраняется.

Проверки: API допуска/отказа выравнивания, очистка очереди по политике источников, повторная проверка исполнителем, перезапуск с сохранением результатов, явное продолжение без повтора готового элемента, сохранение отмены и лимитов. Синтетические проверки не подтверждают музыкальную точность таймкодов.

Если SQLite сообщает о блокировке каталога после завершения ASR, обработчик до трёх раз пытается сохранить тот же результат. Перед каждой попыткой он проверяет разрешение на действие и ревизию файла. Если сохранить результат не удалось, задача сообщает об этом. При блокировке запроса интерфейс предложит проверить результат действия и повторить его при необходимости.

После восстановления публикации Ready квитанция содержит идентификатор операции и SHA-256 ревизии. Старая квитанция дополняется при чтении, только если задача, трек, вид операции и доступные сведения о ревизии однозначно совпадают с записью истории. Чтение не запускает повторную публикацию и не меняет старую квитанцию. Реле Music по-прежнему проверяет факт публикации, ревизию и принятие результата перед копированием.

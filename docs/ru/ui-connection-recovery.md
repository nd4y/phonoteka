# Восстановление соединения в UI

После перезапуска сервера или обрыва соединения запрос браузера может остаться без ответа. Это не должно навсегда останавливать процент на прежнем значении или оставлять журнал задач в состоянии подключения.

Чтение JSON (GET и HEAD) ограничено 25 секундами, включая получение тела ответа. Отмена со стороны вызывающего компонента сохраняется. При таймауте опрос статуса и журнал задач освобождают ожидающий запрос, а очередное плановое чтение может восстановить данные без перезагрузки страницы. Последний видимый прогресс остаётся на экране вместе с ошибкой обновления; потеря связи не означает нулевой прогресс или сбой задачи.

Ошибка обновления статуса отделена от ошибок действий с коллекцией. Успешное обновление снимает свою ошибку, сохраняя независимые ошибки действий. Если прокси возвращает текстовый 404 без ответа приложения, интерфейс сообщает о недоступности сервиса. При неизвестном результате записи сначала проверьте «Обработку» и только потом повторяйте действие.

Клиент не повторяет запись автоматически из-за таймаута, ошибки прокси или потери связи. Прежнее однократное обновление явно отклонённого CSRF-токена в режиме без входа сохраняется. Авторизация, трейсинг, допуск задач и правила принятия данных коллекции не меняются.

Регрессии проверяют зависание до заголовков и во время чтения JSON с сигналом отмены, очистку после отмены, следующее успешное чтение, восстановление журнала без перезагрузки и отсутствие повтора записи после 404 прокси. Причина перезапуска сервера требует отдельных свидетельств; проверки восстановления не подтверждают OOM.

# Память отчёта коллекции

Отчёты JSON и CSV читают метаданные текущих файлов по одной записи. Из результатов
анализа выбираются только ревизия, статус и список состояний провайдеров, нужные
отчёту. Кэшированные обложки и черновики ASR не накапливаются в памяти для всей
коллекции сразу.

Отчёт по-прежнему строится по одному снимку чтения базы. Значение устаревших
результатов, ограничений источников, подготовленных CUE/аудиофайлов и последних
исходов обработки не меняется. Выводятся коды состояния, а не закрытые сообщения
провайдеров или непринятый текст расшифровки.

Регрессионная проверка использует 72 синтетических трека: по 128 КиБ служебных
метаданных и 128 КиБ черновика на трек. Для JSON и CSV выделения памяти Python
должны оставаться ниже 12 МиБ с сохранением строк отчёта и состояний источников.
Это проверка роста памяти отчёта, а не гарантия RAM всего сервиса и не замена
проверке установленной коллекции.

Счётчики и категории проверки читают сохранённый текст и предложение одной
записи за раз. Регрессия проверяет 72 синтетические записи с полями по 96 КиБ:
значения счётчиков сохраняются при пике выделений Python ниже 4 МиБ. Автоматическое
обновление статуса во вкладке пропускает интервалы, пока ждёт предыдущий ответ.
Обновление по явному действию пользователя остаётся доступным.

# Фонотека

Однопользовательское приложение в Docker с обязательной авторизацией. Фонотека работает с копией музыкальной коллекции: показывает теги, обложки и синхронизированные тексты, позволяет проверить изменения перед записью и публикует принятые версии для Poweramp на Android.

Выпуск `0.4.0-alpha` включает внешние каталоги MusicBrainz/LRCLIB/Cover Art Archive, локальный ASR, сопоставление текста с аудио, ShazamIO, извлечение CUE, производные FLAC/WAV для остальных декодируемых форматов, ReplayGain трека и альбома, отчеты, API-токены, расписание и экспорт Ready. Результаты сохраняются как предложения для проверки. [Текущие возможности и ограничения](docs/current-release.md) и [статус реализации](docs/implementation-status.md) отделяют работающие функции от полного объема v1.

## Запуск

Образ linux/amd64 собирается и проверяется в GitHub Actions. Конфигурация: [compose.yaml](compose.yaml), [.env.example](.env.example), [порядок установки и отката](docs/deployment.md). Production требует HTTPS. Для записи нужны проверенные mounts, общий storage guard и явно включенный режим записи.

App и worker используют один образ. ASR работает в отдельном контейнере с локальной моделью и ограничением ресурсов. App читает музыку, worker выполняет ограниченное число задач в фоновых потоках. SQLite/WAL хранится локально, отдельно от оригинала и рабочей копии. Оригинал доступен только для чтения. Теги изменяются без перекодирования с проверкой аудиопакетов и резервной версией.

## Разработка

```sh
python3 -m venv .venv
.venv/bin/pip install -c requirements.lock '.[test]'
.venv/bin/python -m pytest -q
cd frontend
npm ci
npm test
npm run build
```

Медиатесты требуют Linux, FFmpeg, FFprobe и libebur128-1. Интеграционный тест `python3 tests/container_smoke.py` использует отдельно собранный `phonoteka:ci`, два изолированных контейнера и синтетическое аудио. Он не обращается к коллекции владельца или внешним музыкальным сервисам.

## Проектные материалы

- [Техническое задание](docs/specification.md): версия 1.4, один owner/login/API-токены, Docker, async/потоки, ACRCloud/AudD, MusicBrainz/AcoustID/CAA/LRCLIB, TheAudioDB/Discogs, ASR/выравнивание, аудит/сравнение дублей/комплектность альбомов/ReplayGain, безопасная запись, Music_Ready/телефон и 84 критерия приемки.
- [Ревью и предложения](docs/review-v1.4.md): исправленные риски, обоснования, проверка форматов/Poweramp до полной реализации и отдельные предложения на следующие этапы.
- [Матрица покрытия обсуждения](docs/discussion-coverage.md): где зафиксированы все согласованные функции и какие интеграции опциональны либо отложены.
- [Описание дизайна](docs/design-notes.md): Material 3 Expressive, светлая/темная темы и адаптация к телефону.
- [Интерактивные макеты](docs/design-mockup.html): коллекция, проверка метаданных, редактор таймкодов и параллельная обработка. Макет содержит демонстрационные данные и не изменяет музыку.

Рабочая коллекция первоначальной установки: `\\192.168.0.10\media\Music_Work_2026-10-17`. Копия всех 2105 файлов проверена полным SHA-256 17 октября 2026 года в 22:22 МСК. Это датированный результат подготовки, а не непрерывная проверка состояния. Программа не зависит от этих частных путей. Отчеты подготовки и снимки макетов находятся вне репозитория в `../output/music-library/`.

Обработка и публикация выполняются отдельными действиями владельца. Публикация Ready не означает доставку на телефон или проверку отображения в Poweramp. Автоматическое изменение всей коллекции при запуске отсутствует.

В первой версии нет регистрации, многопользовательских ролей, tenant-модели, биллинга и центрального SaaS. OIDC и n8n подключаются по настройке. Коммерческие lyric-провайдеры требуют подходящего доступа/условий встраивания; Spotify/Apple Music/Last.fm/Fanart.tv/ShazamKit зафиксированы как резерв последующих интеграций, без обязательной зависимости ядра.

Прежний интерактивный макет показывает четыре демонстрационных экрана. Исполняемый интерфейс находится в `frontend/` и получает данные из API. Наличие экрана или требования в документе не является подтверждением реализации внешней интеграции.

Ревью v1.4 уточнило одного писателя work/Ready, восстановление состояния вместе с файловыми версиями, бюджеты при параллельной работе, отзыв фоновых полномочий, качество ASR, сохранение ID3/LRC и шкалу времени превью. Целевой объем v1 сохранен; разработка начинается с технических проверок R0 и ручного сквозного цикла R1. Пункты приемки пока являются требованиями.

Автоматизация и доставка: [API, расписание и экспорт](docs/automation.md). Дополнительные каталоги: [профили источников](docs/catalogs.md).
